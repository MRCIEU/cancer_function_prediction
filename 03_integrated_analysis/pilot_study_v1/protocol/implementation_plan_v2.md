# 实施计划 v2

正式样本冻结和正式实验都还没有开始。本文件替换 v1 里“先抽完 shared 再考虑独有文章”以及“模型跑完后按可比与不可比各半补足”的做法。

## 和上一版抽样的差别

每个 pair 的来源层按该 pair 自己的 pair–PMID 关联分成 shared、CORE-only、SemMedDB-only。每个非空层先取 1 篇，再在仍有剩余的层之间轮转，直到 6 篇或候选用尽。层内排序使用 seed 20261017。不先把 shared 抽满。

shared 同时计入两个库的篇数，唯一 PMID 只计一次。这个启动方案要求每个库至少 2 篇。达不到就记为不满足启动方案，不改规则凑数。

开发 pair 整对排除。其他 pair 只去掉正文已经暴露的 PMID，再用剩下的文章判断是否够格。一篇开发 PMID 不排除该 pair 的其余文章。只出现过 PMID 的记录保持 pmid_listed_only。暴露信息缺失保持 residual_leakage_risk。

人工案例在看模型输出之前确定。每个文章对和 Q_EXPR、Q_PROG 都进入候选索引，不要求已经有 finding。每 pair 最多 6 个案例，总共最多 24 个。优先顺序是：非空来源类别覆盖，然后两类问题尽量平衡，然后固定排序补足。不足就记录，不按模型输出换例。没有“大约一半可比、一半不可比”的配额。

每篇提取只调用一次。失败、零 finding 和合法无法判断留在分母里。

## 阶段入口

1. 规范试用。入口是本 child 的 phase_a 和 phase_b，评阅者尚未确定。真人先填 A，锁定后再看 B。本阶段不跑正式样本。停止条件：没有真实填写记录。

2. 按试用修订规范。入口是锁定的 A 记录和随后的 B 记录。原 A 答案不回改。若 schema 或 prompt 改变，只对受影响的开发单元做技术回归。

3. 独立样本冻结。入口是修订后的合同和本文件里的抽样函数。本轮该函数对真实框架关闭。

4. 正式流水线、有限人工评价、分析。入口是已冻结且未暴露的文章。规模仍是 4 个新 pair、每 pair 4 到 6 篇、最多 24 个唯一 PMID、最多 24 个案例。这是启动规模，不是功效分析。

评阅者未定时，不提交等待人工的作业，也不自动进入冻结。
